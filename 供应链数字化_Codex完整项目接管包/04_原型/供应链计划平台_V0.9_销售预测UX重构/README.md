# 供应链计划平台 V0.9：销售预测 UI / UX 重构

本版本在 V0.8 基础上重构销售预测模块，视觉和交互对齐商品主数据中心类型的企业后台列表页。

## V2 信息架构

本轮将 PMC 的“发起 / 关闭销售填报”与销售运营的“维护销量预测”拆开：

- PMC：`计划配置 → 计划参数 → 销售预测周期`
- 销售运营：`销售预测`
- 不新增“预测任务”“预测周期”“填报管理”“预测版本”等菜单。
- `销售预测`只保留销售运营的 W 周期填报、保存和提交。
- `计划参数 → 销售预测周期`承载周期规则、本期预测任务、发起窗口、关闭填报和进入审核。

## 企业后台视觉与列表重构

- 左侧改为浅色企业后台导航，移除深蓝色控制台侧栏。
- 移除 `PLAN CONTROL CENTER` 品牌区。
- 移除 workspace tabs，不再把工作区 Tab 作为主要业务导航。
- 顶部增加全局搜索、通知、角色切换和用户信息。
- 保留业务菜单：销售预测、备货计划、调拨计划、货权管理、数据中心、计划配置。
- 计划配置页标题显示为“计划参数”，使用“计划基础参数 / 销售预测周期 / 供应商参数 / 物流参数 / MOQ规则”Tab。
- 销售预测改为标准列表页：面包屑、轻量周期信息条、W周期 Tab、状态 Tab、查询区、工具栏、列表和分页。
- 销售预测列表改为核心字段 + 信息组：
  - 商品
  - 国家/站点
  - 销售负责人
  - 商品标签
  - 历史销量
  - AI预测
  - 销售最终预测
  - 库存/在途
  - 在库 DOI
  - 异常
  - 状态
- 商品、标签、历史销量、库存/在途、AI预测的底层字段进入 Popover、行展开或商品详情 Drawer。
- 在 1366px 桌面宽度下，列表容器不产生内部横向滚动；W1-W5 通过 Tab 切换，不横向铺开。
- 商品详情 Drawer 支持预测结果、销售历史、库存与在途、商品信息、操作记录五个 Tab，并保留原始商品身份字段。

## PMC 预测周期配置与发起

PMC 在 `计划配置 → 计划参数 → 销售预测周期` 中完成本期任务发起：

1. 预测周期
   - 选择预测月份，例如 `2026年10月`
   - 选择本轮需维护 W 周期数，例如 `4` 或 `5`
   - 系统根据计划日历自动生成 `W1 10/01-10/07`、`W2 10/08-10/14` 等周期
2. 填报窗口
   - 设置销售填报开始时间
   - 设置销售填报截止时间
   - 明确销售在窗口内维护本轮 W 周期销量预测
3. 确认发布

确认发起后：

- 周期状态从“待发起”变为“销售填报中”。
- 初始填报进度为 0%，每个 W 周期进度为 0%。
- `销售预测周期`区域显示需维护 W 周期数、各 W 周期日期、填报时间、填报进度和 W 周期进度。
- PMC 可查看任务、调整截止时间、关闭销售填报并进入审核。
- 关闭后状态进入“销售填报已关闭”，销售端变为只读。
- 同一预测月份不重复创建新任务，需通过现有状态流转进入审核、退回和重新提交。

## W 周期销售填报

- 计划参数页的“发起本期销售预测” Drawer 第一阶段支持将 W 周期数从 4 改为 5，页面立即增加 W5。
- W 周期日期由计划日历逻辑生成，不在销售预测页面手工维护。
- 销售运营通过 W Tab 切换当前维护周期，PMC在配置页查看任务进度。
- 列表只展示当前 W 周期数据，避免把 W1/W2/W3/W4 横向铺成多组字段。
- 商品详情 Drawer 增加多 W 周期矩阵，一次查看同一商品的 AI预测、销售预测和调整量趋势。

## 预测周期状态机

当前原型已实现：

```text
待发起
  ↓ 开启销售填报
销售填报中
  ↓ 关闭销售填报
销售填报已关闭
  ↓ 进入审核
待PMC审核
  ↓ 通过 / 退回
预测确认 / 待销售修改
  ↓ 销售重新提交
待PMC审核
```

同一预测周期处于“销售填报中 / 销售填报已关闭 / 待PMC审核 / 待销售修改 / 预测确认”等状态时，不再显示“开启销售填报”，避免重复创建同一轮预测。

## 角色交互

- PMC：开启、调整、关闭窗口；批量确认；批量退回；查看全部信息。
- 销售 / 运营：在开放窗口内编辑销售最终预测，修改时必须填写调整原因，提交后进入 PMC 审核。
- 采购：第一版只读查看。
- 管理者：只读查看。

