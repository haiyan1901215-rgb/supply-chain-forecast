# 计划配置重构 · 2026-09-25 · config12

## 当前决策 · V0.3.29 · 2026-10-03

- 按本轮明确授权，销售母版仅增加只读PMC基准、批次/参数版本和非数值预测状态；人工与活动仍原位填报。PMC台账改为系统预测、PMC基准、最终预览三条线，不再提供销售日级人工填报。
- PMC校准是独立于系统预测的批次覆盖记录，支持ADU/比例、原因、撤销、审计；重新计算保留记录。父体校准后按现有份额拆分；子体单独校准会改变父体PMC合计，系统父体池不变，此影响在编辑时明确提示。
- ADU校准保留系统日曲线，按目标ADU缩放；比例校准按系统值调整。仅数值日期参与ADU及汇总；沿用既有整数分配方式。没有自行实现Clean/EWMA/季节算法。
- 季节等待状态来自上游日级状态或已导入月度人工启动标记，数值为null，不用0代替；等待状态禁止PMC和销售覆盖。缺失的模型结果仍阻断发布，明确等待状态作为可见提醒保留。
- 参数默认次日/后续批次生效，不伪造模型服务即时重算。本批次参数切换只在已有计算能力支持范围内应用，未接入的趋势模型参数只引用来源。
- 沿用现有表格、时间轴、控件和门户布局；共享预测线定义、非数值状态与汇总规则。V0.3.29继续以销售台账为母版，收敛顶部层级、预测线语义、份额依据和校准交互，并进行角色/数据回归。

## 当前决策 · V0.3.27 · 2026-10-03（优先于下方历史记录）

- 预测批次详情是销售预测台账的 PMC 前置工作台，默认父子树；子体/父体/变体仅为同一台账的数据投影，不是三个页面。
- 保留销售母版的 `.forecast-table` 和原有样式；不修改销售冻结脚本或 CSS。本轮不创建新的 Table、样式系统或规则配置页。
- 删除未挂载的步骤式评估、参数、父子关系、子体拆解、独立结果与销售入口组件，不以注释或隐藏页面保留。
- 份额校准在当前子ASIN下方行内编辑，保留归一化、原因与保存校验。日级预测继续原位编辑；复杂关系、组合与发布窗口沿用现有浮层。
- 顶部主要操作收敛为主流程按钮、参数、重新计算、关系维护、导出、更多；确认关系/拆解、导入、来源与审计收在更多菜单。
- 数仓字段只读，不再提供“编辑全部来源字段”。父体依据默认五项核心值，详细诊断与来源计算式主动展开；不在前端拼装未经来源证实的模型公式。
- 季节规则只引用版本；商品运行模式与预测状态有来源才展示。示例批次引用 SEASON-V3 为原型演示版本，不代表已连接真实规则服务；F10等待实际销量等特殊状态仍由上游输出并按既有待复核校验处理。
- 季节规则版本随结果快照、日级合同和销售清单传递；参数次日生效仍与当前批次结果分离。本轮不改变预测公式。
- 纠正展示口径：趋势与价值按语义读取，90天数值只汇总前90个预测日，历史对比只使用上批预测与本批实际共有的日期并隔离店铺。
- 边界：这是内存演示原型。当前页面刷新会恢复演示数据；发布是同一原型内快照切换，不是对生产销售系统的网络推送。数仓接入、规则服务、后端持久化与权限不在本轮伪造实现。

### 本轮设计检查

沿用既有主题、Ant Button/Dropdown/Form及反馈组件；用户指定的销售自定义台账是明确保留项。没有新增 CSS 覆盖、主页面或状态步骤条。批次维护增强不修改销售母版；交互、发布数据一致性与视口回归记录见 V0.3.27 验证说明。

## 本轮用户已明确

- 计划配置分为预测规则、父子关系、预测参数；父体总量规则与子体份额规则分别维护。
- 本轮子体基础份额采用 Clean 销量。84/14、70/30、ADU < 2 且有销量天数 ≤ 10 为可配置标准规则，不是固定算法常量。
- 预测批次绑定父体规则、拆解规则、参数、关系版本。已绑定的历史快照不随新规则或父子迁移改变。
- 人工调优是指定批次实例；只维护份额，父体总量锁定，子体合计100%。关系变动和份额调优是不同操作。
- 演示切换的是业务状态，不是原型迭代对比，不需要切换账号。

## 原型实现决策

### V0.3.30 第三轮收敛 · 2026-10-03

- 沿用销售填报同源台账，不新增分析页、步骤导航或 Dashboard；上下文移除预计90天、常驻历史卡、正常风险标签和每日规则标签。
- 主行统一系统预测、PMC校准、最终预测；子体份额按需显示依据。四类配置各自保存，已保存的配置变更不再触发全局保存按钮。
- 重算明确全部父/子/预测日范围，默认保留PMC校准，也可显式清除校准；关系、份额和组合配置不被清除，历史结果快照保留。
- 份额/关系/组合修改提供影响预览和版本；发布前逐日校验父子平衡，F10待实际销量保持非数值。日级校准必须保存日期和备注。
- 参数默认生成后续批次版本；应用当前批次须明确确认并重算。演示模型仅重用上游结果和批次分配，不声称实现数仓模型。

- 在用户当前 pmc11 预览地址内迭代；保留旧模块源文件，切换到新的 config12 模块。无需用户再批准一个候选版本。
- 规则编辑产生新的不可变规则版本，关系草稿显式选择使用哪个版本。参数修改产生新参数版本；已保存规则内显式参数优先，参数版本提供默认值并记录数据口径。
- 规则优先级数字越小越优先；相同优先级按规则编码稳定排序，只命中一条。默认规则兜底。
- 关系草稿可编辑，待确认可退回草稿，已生效/已冻结/历史只读；已生效版本可冻结。冻结后不能解冻改写，后续批次从快照新建。
- 历史销量按国家+子ASIN重归集，并保留店铺维度隔离，避免US与UK或不同账号同ASIN串数。
- 百分比以万分点保存，整数件数按最大余数法分配，确保份额100%及子体数量之和等于父体总量。
- 自定义规则提供安全的“历史份额保底”业务模型，不执行用户脚本。固定/人工比例要求完整子体映射。
- 演示数据为本地样本；关系变更后的父体需求采用样本子体需求重新归集，用于展示流程，不能视作数仓预测算法已实现。
- 新模块使用独立 localStorage 键，保留现有销售提报缓存；写入失败不显示成功，不覆盖损坏存储。

## 本轮交付边界

实现可交互、本地持久化的规则模型、关系生命周期、份额调配、迁移、审计和反查。未接真实数仓、后端权限、多人并发服务；并发浏览器写入使用修订号检测。真实父体预测与下游SKU/采购计算继续保留原有职责边界。

## 预测批次同源台账补充决策 · 2026-10-02

- 预测批次详情复用销售预测台账的固定信息列、周/日日期列和预测线结构；销售页面本身不调整。
- 桌面宽度固定选择、商品详情、尺码、销量/库存、预测线五个叶子列；窄屏解除固定并在台账内部横向滚动，避免固定列总宽遮挡全部日期列。
