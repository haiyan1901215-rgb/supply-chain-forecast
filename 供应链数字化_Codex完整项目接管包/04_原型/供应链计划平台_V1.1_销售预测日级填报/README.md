# 供应链计划平台 V1.1：销售预测日级填报原型

## 版本定位

本版本基于 V1.0 配置中心原型继续迭代，独立新增“销售预测日级填报”版本，不覆盖 V1.0。

本轮只重构两个相互衔接的业务对象：

1. `计划配置 → 计划参数 → 销售预测周期`：PMC 发起、调整窗口、关闭填报和进入审核。
2. `销售预测`：销售运营按 W 周期进入商品清单，并在右侧 Drawer 内按天维护预测。

核心原则：

```text
W 周是任务管理单位，天是销售填报单位。
```

## 当前菜单范围

本 V1.1 原型保留以下业务菜单：

- 销售预测
- 备货计划
- 调拨计划
- 计划配置

已删除“货权管理”和“数据中心”菜单及对应页面入口。两者不再参与导航、页面渲染或角色切换；现有销售预测、备货计划、调拨计划和计划配置 Mock 数据与交互保持不变。

## 角色边界

### PMC

PMC 在计划参数中：

- 发起本期销售预测；
- 设置需维护 W 周期数；
- 设置和调整销售填报窗口；
- 查看进度；
- 关闭填报；
- 进入审核、确认或退回。

PMC 不在销售预测页面开启或关闭填报。

### 销售运营

销售运营只在销售预测页面：

- 切换预测月份和 W 周期；
- 查看商品、历史销量、库存/在途和 AI 基准；
- 进入明确的“填报”入口；
- 按日维护人工修正基准 ADU 和活动当天销量预测；
- 保存草稿或提交本 W 预测。

销售运营不能修改 W 周期数量、填报窗口或 PMC 状态。

## 页面结构

### 计划参数：销售预测周期

页面包含：

- 周期规则：月度、按计划日历生成 W 周期、默认 W 周期数、月底发起规则；
- 本期预测任务：预测月份、状态、需维护 W 周期数、填报窗口、进度和操作按钮。

“发起本期销售预测”使用三步 Drawer：

1. 选择预测月份和需维护 W 周期数；
2. 设置填报开始/截止时间；
3. 确认发起。

W 周期日期由 `buildWeeks()` 根据计划月份生成，PMC 不手工输入日期。修改 4 个 W 周期为 5 个时，会立即生成 `W5 10/29-11/04`。

确认发起后：

```text
状态 = 销售填报中
进度 = 0%
已提交 = 0
W 周期进度 = 0%
```

本版本使用独立的 `v11-confirm-window` 事件完成最终确认，避免被旧版本 `confirm-window` 监听器覆盖。

### 销售预测列表

主列表采用标准 B 端后台布局：

```text
页面标题
→ 当前预测周期摘要
→ W 周期 Tab
→ 状态 Tab
→ 查询区
→ 列表工具栏
→ 商品预测列表
```

主列表只承担“我有哪些商品需要填”的定位任务，不展开成超宽日级表格。

列表核心字段：

- 商品复合身份；
- 国家/站点；
- 销售负责人；
- 商品标签；
- 历史销量；
- 库存/在途；
- AI 基准 ADU；
- 活动；
- 最终预测；
- DOI；
- 异常；
- 状态；
- 操作。

“展开”只显示紧凑预测依据；真正的填写入口是“填报”。销售端不显示 PMC 的发起、关闭和调整截止时间操作。

### 日级预测填报 Drawer

点击“填报”或“修改”打开约 1000px 宽的 Drawer。Drawer 同时展示当前 W 周期的 7 天：

```text
日期作为列，预测线作为行
```

主要预测线：

1. `系统基准 ADU`：数仓/预测模型结果，只读；
2. `人工修正基准 ADU`：销售对正常销售基准的人工修正，可编辑；
3. `活动当天销量预测`：活动带来的额外影响，可编辑；
4. `最终合并预测`：系统自动计算，只读；
5. `该日取值来源`：系统根据修正和活动自动生成，只读。

计算关系：

```text
最终合并预测 = 人工修正基准 ADU + 活动当天销量预测
```

当人工修正等于系统基准时，最终来源为“系统基准”；发生人工修正时为“人工修正”；存在活动时增加“活动填报”；两者同时存在时为“人工修正+活动”。

活动影响是结构化数据，不是备注，支持：

- 活动类型；
- 活动名称；
- 活动影响销量；
- 备注。

人工修正基准 ADU 与系统基准不一致时，必须补充调整原因。错误会回写到对应日期和字段，不只依赖全局 Toast。

Drawer 还包含：

- 紧凑预测依据；
- 查看完整数据 Popover；
- W 周预测汇总；
- 保存草稿；
- 提交本 W 预测。

## 状态流转

```text
待发起
  ↓ PMC确认发起
销售填报中
  ↓ PMC关闭 / 截止时间到期
销售填报已关闭
  ↓ 进入审核
待PMC审核
  ├─ 确认 → 预测确认
  └─ 退回 → 待销售修改
                 ↓ 重新提交
               待PMC审核
```

提交后销售端进入只读查看。PMC 退回时必须填写原因，销售重新进入同一个日级 Drawer 修改并重新提交，不创建新的预测周期。

截止时间自动到期时记录关闭原因“截止时间到期”；PMC 主动关闭时记录“PMC手动关闭”。PMC 延长到未来时间后，Mock 状态恢复为“销售填报中”。

## Mock 数据覆盖

当前 Mock 包含 30 条商品记录和每个 W 周期的 7 天数据，覆盖：

- 无活动；
- 有活动；
- 人工修正；
- 未人工修正；
- 待提交；
- 已提交；
- 待销售修改；
- 已确认；
- DOI 异常；
- 预测异常。

系统基准 ADU 以加权日均销量按日拆分，避免把旧版周汇总值直接作为日级 ADU 展示。示例商品 `BR-00618-Y1-M` 的 W1 系统基准约为 `5.1`，与加权日均 `36` 的数量级一致。

## 与配置中心的边界

V1.1 不重新设计预测算法，也不把以下内容变成配置：

- 近 3/7/15/20/30 日销量；
- TrendRate；
- ADU0；
- 父体/子体预测 ADU；
- 需求缺口；
- DOI；
- 实际销量。

这些仍属于数仓计算结果。销售人工修正、活动影响、保存草稿、提交和 PMC 审核属于业务操作结果。

配置规则、生命周期、商品映射、预测规则、备货策略、物流策略仍由 V1.0 配置中心承载。

## 运行方式

可以直接在浏览器打开：

```text
index.html
```

如果需要本地 HTTP 预览：

```bash
python3 -m http.server 8792 --bind 127.0.0.1
```

推荐验收尺寸：

- `1366 × 768`
- `1440 × 900`

## 完整源码 TXT 备份

项目目录内的 `generate-source-txt.cjs` 可重复生成完整源码归档：

```bash
node generate-source-txt.cjs
```

默认输出：

```text
供应链计划平台_V1.1_销售预测日级填报_source.txt
```

归档包含当前目录下的 HTML、README、验证记录和证据资源；文本文件保留原始内容，二进制资源使用 Base64，并为每个文件记录相对路径、类型、原始字节数和 SHA-256。生成的 TXT 本身不会被再次收入归档，避免递归膨胀。
