## 二、当前系统现状

### SCM
已有自建 SCM，主要涉及下单处理、采购订单相关处理，并将订单内容推送到领星。业务已经使用过一段时间。

主要问题：与PMC计划、MES生产、库存等系统之间尚未形成完整数据串联，因此Q4不应简单理解为“重新做SCM”，而应先做现有能力盘点、保留/重构判断和系统串联。

### MES
已有外采源代码MES，使用程度不高。当前方向：Bug修复、微调、工厂现场排查、推广使用；一期不是默认重新开发MES。

### PMC
当前是本阶段重点。部分计划、备货工作依赖人工表格。典型方式：销售预测 + 当前库存 + 在途库存 + 历史销量 + FBA需求 + 业务调整 → Excel计算 → 采购/备货计划。

核心问题不是“没有计划页面”，而是计划计算过程、输入数据和调整过程没有形成统一线上业务链。

### 面辅料
相关系统能力基本空白。需要确认：物料主数据、BOM、物料需求、采购、到料、齐料、生产关联、库存关联。不能直接认定必须独立系统。

### QC
相关系统能力基本空白。需要确认来料检、产中检、成品检、抽检、放行、不合格、返工、退货、异常闭环。暂时不能直接定义成完整QMS。

### 库存
当前库存数据线上化不足。需要从采购在途、工厂库存、物流在途、海外仓、FBA、渠道库存、可用库存、预占、共享库存等角度确认数据来源、权威系统和计算关系。

此前库存讨论属于另一家公司，只能借鉴数据治理方法，不能把过去公司的具体业务规则当作当前公司事实。

## 三、当前As-Is核心问题

1. 计划依赖人工：Excel同时承担数据汇总、计算、人工调整、计划输出。
2. 系统之间断开：PMC、SCM、MES、领星、库存、未来QC、未来面辅料没有完整链路。
3. 计划与执行脱节：计划可能在Excel，SCM人工下单，MES独立运行/使用不足，库存数据不完整。
4. 数据无法形成闭环：采购计划变化后，采购、生产、库存、计划是否同步缺乏线上闭环。

## 四、当前建议的As-Is业务链

# 03｜供应链系统边界与数据流 V0.1

## 一、总体原则

系统边界不是按照部门划分，而是按照：

> 谁产生业务对象、谁负责业务动作、谁是数据Owner、谁消费数据。

## 二、初步系统边界

### 商品主数据中心
负责SKU、SKC、商品基础属性、商品关系。供应链系统只消费。

### PMC计划系统
核心职责：把需求转换成供应链计划。

候选负责：销售预测接收、FBA过货计划、库存需求匹配、缺口计算、采购计划、人工调整、计划冻结、计划结果输出。

### SCM
核心职责：把计划转化为采购执行。

负责候选：采购订单、供应商确认、采购执行、到货跟踪、与领星连接。

### MES
核心职责：生产执行。

负责：生产任务、工序、生产进度、完工、生产异常。

一期重点：修复已有MES并推广。

### QC
候选职责：质量执行。

负责：质检任务、检验、结果、不合格、整改、放行。当前为空白，是否进入Q4需要确认。

### 库存/WMS
核心职责：实际库存和库存动作。

负责候选：入库、出库、库存余额、可用库存、在途、库存调整。实际权威系统待确认。

### 面辅料
当前不确定是：A独立系统；B SCM内能力；C PMC/MRP + SCM协同能力。必须通过业务对象判断。

## 三、系统数据流

### 商品
商品主数据中心 → SKU/SKC → PMC → SCM → MES

### 需求
销售预测 → PMC

### 计划
PMC → FBA过货计划 → 采购计划 → SCM

### 采购
SCM → 采购订单 → 供应商；SCM → 领星

### 生产
SCM → MES；MES → 生产进度/完工 → SCM/库存【待确认】

### QC
MES/SCM → QC；QC → 合格/不合格 → MES/SCM/库存【待确认】

### 库存
WMS/库存系统 → PMC；库存数据作为计划输入。

## 四、核心数据闭环

销售预测 → 计划 → 采购订单 → 生产 → 质检 → 入库 → 库存 → 计划重新计算 → 下一轮采购。

## 五、一期不建议做

一次性建设完整SRM、完整PMS、完整QMS、完整WMS、完整MRP、完整供应链控制塔。

原因：系统依赖复杂、周期长、业务规则尚未稳定。

## 六、Q4建议关注

### P0
PMC：销售预测 → 过货计划 → 库存匹配 → 采购计划。

### P1
SCM：采购计划 → 采购订单 → 领星；MES：已有系统修复 → 生产执行 → 状态回传；库存：提供计划所需的基础库存数据。

### P2/待确认
QC、面辅料、PMS、更复杂MRP。

# 05｜MVP规划与业务对接方法

## 一、不要按“系统”规划Q4

不要简单规划为：做MES、做PMC、重构SCM、做面辅料、做QC、做库存。

问题在于：可能做了6个系统，却没有形成一条真正闭环的供应链流程。

Q4应按照业务主链规划。

## 二、建议用一条主链统领Q4

销售预测 → FBA过货计划 → 库存匹配 → 采购计划 → 采购订单 → 生产/采购执行 → QC → 入库 → 库存 → 下一轮计划。

再从这条链判断：哪些能力必须建设、哪些能力复用、哪些系统需要重构、哪些暂时不做。

## 三、MVP判断模型

每项需求用四个维度评价：

### 业务价值
- 高频
- 核心
- 影响金额
- 影响人数

### 当前痛点
- Excel
- 人工
- 出错
- 重复录入
- 数据断层

### 系统依赖
- 商品主数据
- SCM
- MES
- WMS
- 领星
- 其他

### 实现复杂度
- 数据复杂度
- 规则复杂度
- 接口复杂度
- 权限复杂度

优先：高价值 + 高痛点 + 可落地。

## 四、建议MVP分层

### P0
PMC核心计划：预测接入、FBA过货计划、库存匹配、缺口计算、采购计划、人工调整、冻结。

### P1
SCM：计划转采购订单、采购执行、领星同步。

MES：Bug修复、微调、关键状态、生产执行。

库存：为计划提供可靠基础数据。

### P2
QC、面辅料、更完整库存、MRP、PMS。

## 五、业务访谈方法

不要直接问“你想要什么功能？”。

应该让业务复盘真实工作，例如：

> “假设今天是周一，你现在要做下周FBA过货计划，请你从打开Excel开始，一步一步告诉我你做什么。”

记录：动作 → 输入 → 判断 → 计算 → 人工修改 → 输出 → 交给谁。

## 六、通过原型帮助业务进入场景

业务容易因为没有具体页面而遗漏需求，因此可以先做验证型原型。

例如PMC工作台显示：待处理计划、本周需求、缺口、异常、待人工确认。

FBA过货计划显示：商品、预测、当前库存、在途、计划过货、缺口。

然后问业务：

> “这张表是不是你实际工作的样子？”

业务通常会开始暴露少字段、粒度不对、库存不能直接计算、部分订单需要排除、需要人工调整等问题。
