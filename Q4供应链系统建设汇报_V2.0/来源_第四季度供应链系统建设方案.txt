1. 概述
1.1 项目背景
随着公司商品规模、销售平台及订单规模持续增长，供应链计划与采购业务逐渐复杂。
目前公司已经具备PLM、商品主数据、SCM、领星、MES等多个系统，但供应链核心业务仍存在较多依赖Excel、飞书群和人工沟通的情况。
当前Q4供应链建设的核心问题并不是“缺少一个采购系统”，而是：
销售需求 → PMC计划 → 采购需求 → 供应商 → 生产 → 品控 → 入库之间尚未形成统一的系统化业务链路。
目前PMC每周通过线下文档同步下单计划，采购还需要结合供应商产能、绩效、成本进行人工分配。
采购下单后，又需要通过供应商库存表、产品目录、面辅料资料等多个线下资料进行核对：
-  是否存在可直接使用的工厂库存； 
-  是否应该使用最新版本SKU； 
-  是否需要特殊包装； 
-  应该分配给哪个供应商； 
-  供应商什么时候能够交货。 
随后再将结果重新录入SCM。
因此当前供应链存在明显的：
数据分散、计划依赖人工、跨系统协作断点、采购决策缺少统一依据、订单执行过程不可视等问题。

---
1.2 方案目的
Q4供应链建设不以“系统功能数量”为目标，而是围绕一条核心业务链路建立系统闭环：
需求预测 → 备货计划 → 采购需求 → 采购订单 → 供应商执行 → 生产 → 品控 → 发货 → 入库
其中：
- PMC负责需求计划与备货计划； 
- MRP负责面辅料需求计算及物料计划； 
- SCM负责采购及供应商协同； 
- MES负责生产过程执行； 
- 库存/领星/数仓提供库存及经营事实数据； 
- 商品主数据中心提供统一商品身份及商品关系。 
最终形成：
计划有来源、采购有依据、供应商有任务、生产有进度、库存有结果。

---
1.3 建设目标
目标一：建立统一的PMC计划入口
将当前销售运营线下填写的销量预测、备货计划逐步系统化。
支持：
-  销量预测填报； 
-  日/周预测； 
-  AI预测； 
-  人工调整； 
-  活动预测； 
-  PMC审核； 
-  SKU拆解； 
-  供应商能力校准； 
-  最终备货计划。 
形成：
销售需求 → PMC确认计划

---
目标二：建立成衣采购计划生成能力
PMC完成最终备货计划后，系统形成采购需求。
结合：
-  商品SKU； 
-  商品版本； 
-  供应商； 
-  供应商产能； 
-  供应商交期； 
-  工厂库存； 
-  在途； 
-  面辅料准备周期； 
-  计划交货日期； 
形成可执行的采购计划。

---
目标三：建立MRP面辅料需求计划
围绕成衣采购计划和BOM建立面辅料需求计算能力。
根据：
成衣采购需求 + BOM + 现有物料库存 + 安全库存 + 损耗
计算：
-  面料需求； 
-  辅料需求； 
-  采购需求； 
-  备料需求； 
-  发料需求。 
现有业务已经明确提出，希望系统根据成品订单和BOM自动计算面辅料需求，并形成采购计划。

---
目标四：打通PMC → SCM采购链路
将PMC最终确认的采购需求直接进入SCM采购计划。
减少目前：
PMC Excel → 飞书群 → 采购人工整理 → Excel → SCM导入
的重复操作。
最终形成：
PMC计划 → PR → 采购分配 → PO → 供应商确认

---
目标五：建立供应商执行跟踪能力
采购下单后，不再主要依靠群聊和Excel追踪。
系统逐步形成：
PO → 供应商接单 → 面辅料到料 → 生产 → QC → 发货 → 入库
的执行状态链。
现有业务已经存在订单执行的多个节点，包括面辅料到料、生产进度、货期确认、供应商发货、到货及质检入库。

1.9 一期核心原则
原则一：计划先于采购
不再以采购人员Excel作为采购起点。
形成：
需求 → 计划 → PR → PO

---
原则二：数据来源系统负责数据正确性
PMC使用库存、销量、商品等数据，但不负责清洗这些数据。

---
原则三：系统做计算，业务做判断
例如：
系统计算：
-  预测； 
-  库存水位； 
-  需求量； 
-  运输周期； 
-  MRP需求； 
-  供应商产能。 
业务负责：
-  是否调整； 
-  调整多少； 
-  为什么调整； 
-  是否批准。 

---
原则四：审批不是新增菜单，而是状态流转
例如：
销售填报
↓
销售提交
↓
PMC审核
↓
PMC调整
↓
最终确认
↓
生成采购需求
而不是：
销量预测菜单 → 销售审核菜单 → PMC审核菜单 → 最终计划菜单……
这样能够避免目前系统菜单越来越碎片化的问题。

---
原则五：以业务单据作为流程载体
核心对象逐渐统一为：
预测单 → 计划单 → PR → PO → 生产订单 → 发货单 → 入库
每张单据通过状态流转完成业务闭环，而不是通过增加菜单承载流程。

2. “Q4关键决策事项”
2.1 PMC与SCM边界
需要确认：
PMC负责“采购什么、采购多少、什么时候需要”；
 SCM负责“向谁采购、以什么采购单执行、供应商如何交付”。

---
2.2 MRP与SCM边界
需要确认：
MRP负责“需要多少面辅料”；
 SCM负责“向哪个供应商采购并跟踪到货”。

---
2.3 库存数据责任
PMC只消费：
-  南沙库存； 
-  工厂库存； 
-  采购在途； 
-  头程在途
-  海外仓可售库存； 
-  预计到货。 
库存事实仍由库存/ERP/数仓提供。

---
2.4 供应商能力数据责任
供应商：
-  产能； 
-  交期； 
-  成本； 
-  准交率； 
-  质量； 
不能全部由PMC人工维护。
应逐步形成供应商主数据/供应商绩效数据来源，PMC只调用。
现有业务中采购已经会结合供应商产能、绩效和成本进行订单分配，因此这一块实际上是后续采购决策系统化的重要基础。

---
2.5 Q4范围控制
Q4先跑通“计划→采购→供应商执行”主链路，再逐步扩展生产、库存、履约。
