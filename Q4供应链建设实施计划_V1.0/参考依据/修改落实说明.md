# Q4供应链建设分层汇报版 V3.0

## 调整结论

本轮按用户提供《修改意见》的最后汇报顺序组织内容：先建立整体框架，再展开模块细节。共10页，不再将范围、字段、状态和实施细节全部塞进一张主流程图。

第1页回答Q4要打通什么，第2页解释系统如何分工，第3页对齐六类角色职责，第4—10页按修改意见分别展开PMC预测、PMC备货、MRP、SCM、供应商执行、MES及库存回流。

## 修改意见落实

| 修改意见 | V3.0落实 |
|---|---|
| 主流程信息过密 | 第1页仅保留七阶段业务主线、醒目回流、四个建设域与数据基础层 |
| 不混淆业务阶段与系统 | 主线写业务阶段，系统名称作为下方责任对应；建设域另列 |
| 基础数据不属于串行业务节点 | 商品主数据、PLM/BOM、领星/库存/数仓及供应商数据移至底部支撑层 |
| MRP不能画成PMC到SCM的必经环节 | 第2页从PMC并行分出成衣采购需求和MRP物料计划；第3页也采用并行分支 |
| 六角色汇报泳道 | 仅保留销售/运营、PMC、MRP、SCM/采购、供应商/MES、仓储/库存 |
| 加强结果回流 | 前3页用加粗回流线和独立“下一轮滚动计划”节点表现闭环 |
| PMC与采购分工 | PMC确定对象、数量和需求日期；采购负责供应商分配、拆并及PO执行 |
| MES已有系统协同 | 明确利用已有MES，展开订单关联、生产进度、延期及完工回传，未表述为重建 |
| QC/入库范围分阶段 | 六角色图合并显示质量节点，但仍保留QC放行、质检入库及分阶段说明 |
| 审批属于状态而非菜单 | 主流程不展示按钮和状态清单；审批、退回与版本在相应模块详细页说明 |
| P0/P1视觉区分 | P0计划与采购主链用蓝/橙，P1 MRP用紫色，已有MES协同用绿色 |
| 不丢失已梳理的PMC内容 | 预测与备货分成两页，保留日级预测、版本、ASIN/SKU关系、旧新版本库存、DOI、时效和供货能力 |

## 页码与内容

1. Q4供应链建设全景

9. MES协同：已有生产执行能力接入
10. 库存与执行回流：下一轮计划

## 继续保留的业务口径

- 三条预测输入不代表将两份自然销量相加。最终预测=选用基准+活动增量；人工修正未填写时采用系统基准。
- PMC确认PR，SCM承载PR/PO管理。触发接口及各级审核权限继续在实施中细化。
- MRP按净缺口发起物料采购，可用库存覆盖部分直接备料/发料，不要求所有成衣订单串行经过MRP再进入SCM。
- 齐料支持生产开工，不作为供应商接单的前置条件。
- 库存与经营事实由来源系统提供；PMC进行计划判断，不承接数据清洗平台。
- QC节点合并到汇报泳道不意味着取消品控部门职责；详细页继续说明来料、产中、成品及质量问题。
- 原方案第1.8节边界表没有随文本提供。本版继续依据其余已提供章节和最新修改意见，不虚构表内结论。

## 交付与编辑
